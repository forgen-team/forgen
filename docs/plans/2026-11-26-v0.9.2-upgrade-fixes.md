# 0.9.2 — 실제 업그레이드에서 나온 결함 2개 (2026-11-26)

0.9.1 을 이 서버에 npm 으로 올린 뒤 직접 써 보고 찾았다. 0.9.1 검증은 "이미 설치된 상태"의 복사본만 썼고 **이전 버전에서 올리는 과정**을 따라 하지 않아 놓쳤다. 새 기능 없음.

| # | 결함 | 완료 조건(사용자가 보는 결과) |
|---|---|---|
| 1 | 업그레이드(`npm i -g`)의 설치 스크립트가 사용자가 `forgen fix` 로 끈 forgen 스킬을 다시 깐다 — 실서버 09:55 에 16개 재생성, 세션 시작 스킬 설명 217 → 986 토큰 | 사용자가 끈 스킬은 업그레이드 뒤에도 꺼져 있다. 끈 기록은 `~/.forgen` 에 남기고(처방 적용 시), 설치 스크립트·`forgen install claude` 가 그 기록을 존중한다. 다시 켜려면 `forgen fix --undo <id>` 또는 명시적 명령. 새 스킬(이전 버전에 없던 것)은 설치된다 |
| 2 | 감사 첫 화면이 이전 버전 판정 방식으로 잰 재생 결과를 경고 없이 보여 준다(실서버: 0.9.0 판정의 "13.5%" 단일 숫자) | 저장된 재생 결과의 판정 판본이 지금 판본과 다르면 첫 화면에 "이전 판정 방식으로 잰 값 — `forgen audit recurrence` 로 다시 재세요"를 붙이고 범위 대신 그 숫자를 그대로 보이지 않는다(또는 옛 값임을 명시). 판본이 같으면 지금처럼 |

## 설계 (계획 비평 반영)
- **끈 기록**: `~/.forgen/state/disabled-skills.json` — `{ "version": 1, "skills": { "<host>:<skill 이름>": { "at": ISO, "fixId": "plugin-off-…" } } }` (host = claude | codex). `forgen fix` 의 plugin-off 처방이 스킬을 끌 때 쓰고, `forgen fix --undo` 가 지운다. 플러그인(settings.json enabledPlugins) 끄기는 설치 스크립트가 덮어쓰지 않으므로 기록하지 않는다(비평 확인).
- **존중해야 하는 설치 경로(전부)**: `scripts/postinstall.js`(Claude 스킬 설치 약 228~239줄, Codex 스킬 `installDevGuideSkillsToCodex` 약 399줄), `forgen install claude`(planClaudeInstall), `forgen doctor --repair`, `src/hooks/session-recovery.ts` 약 451줄(postinstall 이 건너뛰어진 업그레이드를 감지해 보완 설치). 모두 같은 함수(managed-marker 의 스킬 설치)를 지나게 하고 그 함수가 기록을 읽는다. 기록에 있으면 설치하지 않고 한 줄 알림("끈 스킬 N개는 그대로 둠 — 다시 켜기: forgen fix --undo <id>").
- **판정 판본 비교 필드**: 저장된 재생 결과의 `judge.correction.{model,version}`·`judge.pair.{model,version}`(엄격·관대 둘 다)·후보 고르기 판본. forgen 버전만 다른 것은 경고하지 않는다(판정에 영향 없는 업그레이드가 대부분이라 — 영향 있는 변경은 판본을 올린다).
- **같은 종류 후보 점검 결과**(비평): 룰 suppress·settings.json 플러그인 끄기·CLAUDE.md/rules 편집(managed 마커 없음)은 업그레이드가 건드리지 않는다. 위험한 것은 Claude·Codex 스킬 두 곳뿐.

## 검증 (0.9.1 에서 빠졌던 것 포함)
1. **업그레이드 경로 리허설**: 깨끗한 컨테이너에서 0.9.0(npm 공개본) 설치 → 실데이터 복사본 → `forgen audit`·`forgen audit recurrence`(모델은 가짜 판정기)·`forgen fix --kind plugin-off --apply` → 이 빌드로 `npm i -g` 업그레이드 → 같은 명령들을 다시 실행해 **출력 전문**을 남긴다. 판정: 끈 스킬이 Claude·Codex 둘 다 그대로 꺼져 있음(postinstall 경로와, `--ignore-scripts` 업그레이드 뒤 세션 시작 보완 설치 경로 둘 다, `forgen doctor --repair` 뒤에도), 첫 화면에 옛 판정 경고가 뜸, 다시 재면 경고가 사라짐.
2. 실데이터 복사본 사용자 흐름 출력 전문(0.9.1 과 같은 목록)에서 회귀 없음.
3. 리드가 출력 전문을 직접 읽고 조건 대조. build·전체 vitest·lint(51)·self-gate.

## 구현 기록 (fix/v0.9.2)
- **Codex 사본은 판정 근거가 없어 끄지 않음**(1.0 뒤 Codex 사용 기록으로 판정할 때 다시). "30일 안 씀"은 Claude 대화 기록만 보고 낸 판정이라 `forgen fix` 는 `claude:` 기록만 쓴다. 설치 함수는 `codex:` 기록도 형식상 존중한다.
- 공용 설치 함수: `src/host/managed-marker.ts` installDevGuideSkillSet — `planClaudeInstall`(postinstall·`forgen install claude`·`doctor --repair`·세션 시작 보완 설치가 부르는 postinstall)과 `installDevGuideSkillsToCodex`(`forgen install codex`·postinstall Codex)가 모두 지난다. postinstall 의 Codex 전용 사본 함수는 지우고 dist 의 이 함수를 부른다. 기록: `src/host/disabled-skills.ts`.
- **이전 기록 옮기기**: 기록 파일이 없으면 처방 원장(`audit/fix/ledger.jsonl`)의 되돌리지 않은 plugin-off 스킬 적용(백업의 `…/skills/forgen-*` 폴더)을 처음 읽을 때 `claude:` 기록으로 옮긴다 — 실서버처럼 0.9.0 으로 끈 스킬이 0.9.1 업그레이드에서 되살아난 경우도 0.9.2 업그레이드가 다시 끈다. 백업 폴더가 옮겨졌으면 `<FORGEN_HOME>/backups/<회차>/<id>` 로 다시 찾는다.
- 알림 줄은 postinstall·`forgen install`·`doctor --repair` 출력과 세션 시작 보완 설치 로그(`state/self-setup.log`)에 남는다. npm 7+ 는 설치 스크립트 출력을 숨기므로 `npm i -g` 화면에는 보이지 않는다(기존 동작, 리허설은 `--foreground-scripts` 로 캡처).
- 옛 판정 결과: `judgeChanges()` 가 교정·쌍(엄격·관대) 판정의 모델·문안 번호와 후보 고르기(사전 점수 하한·상위 개수)를 지금 값과 비교한다(관대 번호는 결과에 범위가 있을 때만). 다르면 첫 화면 요약 줄은 "이전 판정 방식으로 잰 값 — forgen audit recurrence 로 다시 재세요 (… 옛 값 13.5% — 지금 방식과 기준이 달라 비교하지 마세요)"로 바뀌고, "가장 중요한 발견"의 재발 예시 근거·`fix --report`·`--share`·다음에 할 일에도 같은 안내. `audit --json` 의 `summary.recurrence.staleJudge` 에 다른 항목.
- 리허설 `tests/e2e/matrix/t25.sh`(MODE=postinstall|ignore|repair, LEDGER=strip|keep). 실데이터 복사본의 대화 기록이 실제 기록을 가리키는 심링크라 컨테이너용 사본은 대화 기록 파일을 실체로 복사했고, 작업 폴더는 지침 파일만 담은 뼈대를 `/home/ubuntu` 에 읽기 전용으로 붙였다.
