## 3. 업그레이드 항목

### U1. 범위가 사라지지 않게 (0.8.0, 최우선)
1. 작업 위치를 **호출 시점**으로: 훅 입력의 `cwd` 를 세션별 상태(`state/session-context/<sid>.json`)에 갱신하고, MCP·러너는 그것을 읽는다. 세션 ID 를 못 맞추면 프로세스 cwd, 그것도 프로젝트가 아니면 **미정**.
2. 모든 evidence 에 `origin`(cwd, 최근 만진 저장소 비율, 호스트) 기록. 범위 판단과 별개인 사실 기록.
3. **미정(unresolved)을 전역과 구분**. `this_project_only=true` 인데 프로젝트를 못 찾으면 전역으로 저장하지 않고 `scope_pending` 으로 두고 사용자에게 알린다. 미정 룰은 주입하되 전역 자리를 차지하지 않고 차단에는 쓰지 않는다.
4. 러너의 `project` 판정도 같은 해석기를 쓴다(F5).

### U2. 범위 모델: 저장소 → 작업 공간 (0.8.0)
1. `global > workspace(제품) > repo > path` 4단계. 기존 `projects` 는 repo 로 읽는다(형식 호환).
2. workspace 는 사용자 정의 묶음: `forgen workspace add <이름> <폴더...>`. git 아닌 폴더 허용. 같은 세션에서 함께 쓰인 폴더를 근거로 **제안만** 한다.
3. 범위 결정 = 출처(어디서 나왔나) + 내용(무엇에 적용되나). 내용 판정은 Haiku, 값은 범위와 짧은 이유. **둘이 엇갈리면 확정하지 않고 확인 목록**(F9 때문). 직접 교정은 모델이 명시한 값이 우선.
4. 기존 52개: `forgen scope review` — 제안과 근거 인용을 보여 주고 일괄 승인. 자동 적용 없음, 스냅샷·되돌리기. 기록 없는 룰은 내용 판정만으로 제안하고 그렇게 표시.

### U3. 언제 넣을지 (0.9.0)
1. 세션 시작: 전역 핵심 + 현재 범위만. 홈 시작(null)이면 전역 + 색인("workspace A 룰 18개")만 넣고 전체 주입을 그만둔다.
2. 작업 위치가 바뀌면(훅의 cwd 또는 만진 파일의 저장소) 그 범위 룰을 **그때 1회** 주입.
3. 선택적 발동 조건 `when: {paths, commands}`. 쓰기 직후 최대 2개, 끝내기 직전 최대 4개, 세션당 룰별 1회. 결정적 매칭만.
4. 11-17 문서 §6 "프롬프트마다 관련 룰만 주입" 금지와의 관계: 프롬프트 유사도 선별은 여전히 안 한다. 이 안은 cwd·경로·명령이라는 **사실** 로만 고른다. hard·안전 룰은 항상 주입.

### U4. 꿈꾸기: 룰 저장소 정리 (0.9.0)
1. `forgen dream`: 룰·후보 + 원문 교정을 읽어 **제안서만** 만든다(원본 불변). 유형: 중복 병합 / 모순 / 끝난 일회성 / 폐지 선언 → 대상 은퇴 / 범위 교정 / 개별 사례 → 상위 원칙.
2. 제안마다 원문 인용 필수. 인용이 evidence 에 실제로 있는지 **기계 검사**로 거르고, 남은 것만 사용자에게.
3. 모순은 최신을 자동 승리시키지 않는다(범위가 다르면 둘 다 맞을 수 있음).
4. 룰에 유효 기간(`review_after`)과 작성 주체(user/mined/pack/imported) 표시. 주기: 주 1회 또는 새 룰 N개, 비용 상한.

### U5. 효과 측정 (계측은 0.8.0부터, 판정은 0.10.0)
1. 주 지표: **같은 교정의 재발률**(룰 활성 후 같은 범위에서 같은 뜻의 교정이 다시 나온 비율). 자문 룰도 잴 수 있다. D9 승급 조건의 근거.
2. 보조: 범위 오염률(주입 룰 중 현재 범위 밖), 세션당 주입 글자, 룰별 발동 → 수정 여부.
3. 안 쓰이고 재발과 무관한 룰은 강등 제안. 노출만 많고 효과가 0인 발동 조건은 조건 수정 제안.
4. forgen-eval 에 고정 과제 A/B(현행 vs U1~U3). 정해둔 별도 과제로만 채택 판정, 공개 메모리 벤치 점수는 근거로 쓰지 않는다.

### U6. 이식·확장 (0.10.0)
룰 레코드를 범위·정체성·내용·유효 기간·작성 주체로 정리해 `way` 로 내보내기: workspace/path 룰 → Claude `.claude/rules` `paths`, Cursor `globs`, 중첩 AGENTS.md. 같은 workspace 에 룰이 쌓여 절차가 되면 스킬 초안(기계 검사 → 모델 판정 순).

## 5. 하지 않는 것
- LLM 을 매 턴 불러 관련도 판정(토스 실측 +10초)
- 벡터 DB·그래프 메모리 도입(지금 문제는 검색이 아니라 범위·정리)
- 기존 룰 자동 재분류·자동 삭제
- 추출 프롬프트에 금지 규칙 더 쌓기(Anthropic: 고정 규칙이 선별을 해침). 범위·근거 구조로 푼다

## 6. 위험
- 만진 경로로 정한 위치는 여러 저장소를 오가는 세션에서 흔들린다 → 엇갈리면 미정
- 전역을 줄이다 필요한 룰이 빠질 수 있다 → 미정은 주입, 탈락 룰 목록 표시
- 재발률은 "같은 뜻" 판정 품질에 좌우 → 표본을 오너가 확인한 뒤 공개
