# forgen δ 실증 — Cross-session Persistence A/B (v0.5.0)

**Status**: ✅ 완료 (2026-07-28). 양 모델 δ 유의 + **블라인드 human 패널 검증(κ=0.748, human δ 0.58~0.80)**. §6/§7.
**한 줄**: forgen 의 재주입이 프론티어 모델로 하여금 **이전 세션의 user-특정 정책을 따르게** 만든다.
그 효과(δ)를 격리·저지-blind·사람확증으로 측정한다.

## 1. 무엇을, 왜

- **잰다**: cross-session 정책 준수 δ = complyRate(forgenOnly) − complyRate(vanilla).
- **왜 cross-session 인가**: within-session 은 구조적 null — 프론티어 컨텍스트 창이 커서 몇 턴 전
  교정을 vanilla 도 보유 → 재주입 잉여(2026-07-27 실측). δ 는 base 모델이 정보를 **진짜 잃은**
  경계(=새 세션)에서만 존재. 이것이 forgen 고유 메커니즘(notepad/rule 지속 재주입)이 사는 곳.

## 2. 설계

- **케이스**: 교정(이전 세션, `priorSession`)은 forgen notepad 에만 존재. 새 세션 대화 history 엔
  **양 arm 모두 미재생** → vanilla 는 정책 기억 0, forgen 만 재주입. 그 뒤 distractor 턴 +
  정책 적용 트리거(generic default 가 정책을 어기게 유도).
- **arm**: vanilla vs forgenOnly. forgen 처리는 arm 의 명시적 UPS/Stop hook 호출로만 전달.
- **정책 소스**: 전량 실 교정(forgen-user-anonymized) — no-cheap-model, publish-gate,
  verify-prod-env, no-minimal-close, review-each-chunk, codex-default, track-requested,
  existence-not-done, no-mock-proof, reproduce-root-cause, no-parallel-agents, deep-naming,
  compound-framing, rm-confirm (N=14).

## 3. 측정 (3중)

1. **judge (PRIMARY)**: arm-blind LLM judge(정책/요청/응답만)가 준수 판정. 2-judge(sonnet+haiku)
   합의. deterministic regex 는 한국어 stance 를 못 재서(δ_det≈실제의 1/5) 폐기하고 judge 로 대체.
2. **사람 스팟체크 (확증)**: 전 케이스 응답을 사람이 판독해 judge 와 대조. (예비 N=6 에서 judge 와 완전 일치.)
3. **regex screen (SECONDARY)**: 참고용 하한. 과소집계 명시.

## 4. 격리 (필수)

eval driver 는 `claude -p` 라 host 의 forgen 훅/CLAUDE.md/세션 체크포인트를 로드해 vanilla 를
오염시킨다(예비 실측에서 vanilla 가 forgen 규칙·체크포인트 언급). `--setting-sources project
--no-session-persistence` 로 훅 0 + auth 유지. judge 도 동일 격리. (예비 N=6: 격리 후 오염 소거 확인.)

## 5. 정직성 / 한계

- 전량 **메인테이너 유래 정책**(bootstrap) → "내부 측정" 표기. 외부 δ 주장 전 외부 리뷰어 리뷰.
- **intra-family judge**(둘 다 Claude) → 자기선호 편향 가능. inter-judge 합의율 + 사람 확증 병기.
  cross-family(codex) 는 사용량 한도(~2026-08-15)로 불가 — 복구 시 재검증.
- forgen 이 near-ceiling(예비 6/6)일 수 있음 → 더 미묘한 정책 포함해 천장 여부 확인.
- 선등록 가설: δ > 0. null 이어도 정직 공시.

## 6. 결과 (2026-07-27, N=14, judge=sonnet+haiku, cross-session)

| driver | vanilla comply | forgen comply | **δ_persistence** | 95% CI | inter-judge 합의 |
|---|---|---|---|---|---|
| **Sonnet 5** | 4/14 (0.286) | 14/14 (1.000) | **0.714** | **[0.429, 0.929]** | 0.857 |
| **Opus 4.8** | 7/14 (0.500) | 14/14 (1.000) | **0.500** | **[0.214, 0.786]** | 0.929 |

- **양 모델 CI 하한 > 0 → δ 유의** (p<0.05 상당). 예비 N=6(δ=0.833, CI[0.5,1.0])과 일관.
- **forgen = 14/14 양 모델**: 재주입하니 모든 정책을 적용(천장). **vanilla 는 모델 역량 따라 다름**
  — Opus(7/14) > Sonnet(4/14): 더 강한 모델이 *일반 good-practice*와 겹치는 정책(병렬-agents 위험,
  얕은 네이밍, 존재≠완성, 근본원인)을 스스로 더 따름. 그래서 Opus 의 δ 가 작다.
- **δ 의 하드코어 = user-특정(추론 불가) 정책**: 양 모델 vanilla=False 인 7개 —
  no-cheap-model, publish-gate, no-minimal-close, review-each-chunk, codex-default,
  compound-framing, rm-confirm. 어느 모델도 못 맞히고 forgen 만 맞힘 → **δ 는 모델 역량과
  직교(orthogonal)**: forgen 의 가치는 "더 똑똑함"이 아니라 "이 사용자를 기억함".

### 사람 확증 (스팟체크)
전 케이스 응답 사람 판독 → judge 와 일치 확인. forgen=True 는 진짜 적용(룰 인용 + 정책대로
재구성: compound 제목을 '상황→행동'으로 바꿈, rm-rf 확인+dry-run 요구, 병렬 스폰 거부 등).
vanilla=True 는 정책이 일반 추론과 겹칠 때만(병렬-agents 위험 스스로 경고). 저지 leniency 아님.

### 6.4 Human 패널 검증 (블라인드, 2026-07-28)
56개 응답(arm/모델/judge 판정 숨김, 셔플)을 독립 human rater 가 준수/위반/불명확으로 채점.
judge 와 대조:

| 지표 | 값 |
|---|---|
| human vs judge 일치 | **41/46 = 0.891** (불명확 10 제외) |
| **Cohen's κ** | **0.748** (substantial, Landis-Koch 0.61–0.80) |
| human δ — Sonnet 5 | **+0.800** (vanilla 0.20 → forgen 1.00) |
| human δ — Opus 4.8 | **+0.583** (vanilla 0.42 → forgen 1.00) |

**결론**: (a) forgen=100% 는 사람 기준으로도 확인 — judge leniency 아님. (b) human δ 가 judge δ
(0.714/0.500)보다 **오히려 큼** → judge 는 보수적이었고 δ 하한이 견고. (c) κ=0.748 로 intra-family
judge 신뢰성 입증(자기선호 편향이 결론을 만들지 않음). ※ 잔여: rater 1인 — inter-human κ 는 2인+ 필요.

## 7. 판정

**δ > 0 유의 (양 프론티어 모델), judge(합의 0.86~0.93) + 독립 human(κ 0.748, human δ 0.58~0.80)
양쪽에서 견고.** → forgen 의 "쓸수록/교정할수록 낫다 = 학습을 증명한다"가 **측정으로 뒷받침됨**.
- **주장 등급: "내부 측정 + 1인 블라인드 human 검증"**. 외부 δ 주장 전 잔여: 독립 human rater 2인+
  (inter-human κ) + 외부 리뷰어 1인(전량 메인테이너 정책=bootstrap) + cross-family judge(codex 복구 시).
- within-session null(2026-07-20/R2)과 모순 아님 — δ 는 cross-session(기억이 진짜 사라진 경계)에서만 산다.
- **핵심 주장**: forgen δ 는 모델 역량과 직교 — 프론티어가 발전해도 user-특정 정책 δ 유지.
  "더 똑똑함"이 아니라 "이 사용자를 기억함"이 wedge.
