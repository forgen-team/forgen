# ADR-018: Stop 룰 — 룰별 발동 조건과 실행 증거 판정

- 상태: Accepted (2026-10-07, 오너 합의 "ㄱㄱ")
- 관련: ADR-009(Stop 메타가드), ADR-013(채굴 룰 advisory-only), ADR-017(신뢰 영수증)

## 배경 — 30일 실대화 리플레이

지난 30일 동안 실제 대화의 마지막 답변을 지금 룰에 다시 통과시켜 봤다. 측정 범위는 이 머신의 전 프로젝트이고, 첫 측정은 2,216턴, 최종 측정은 2,671턴이다. 드러난 결함은 다섯 가지다.

1. **제외 조건이 메시지 전체를 봤다.** "끝났습니다. 실패는 없습니다."처럼 다른 문장의 `없습니다` 때문에 정상 완료 보고의 67%를 놓쳤다.
2. **모든 완료 룰이 같은 완료 어휘에 반응했다.** 한 번 걸리면 룰 4개가 동시에 걸렸다. 정작 각 룰이 지키려는 행동은 보지 않았다.
3. **mock 룰은 단어 하나에 반응했다.** 룰 이름을 표에 적기만 해도 차단됐고, 차단과 응답이 반복되는 루프가 7회 있었다. forgen 저장소에서는 커밋된 프로젝트 룰(`.forgen/rules`)이 사용자 룰을 덮어서 이 현상이 특히 심했다.
4. **critic 룰은 자기 신고로 통과했다.** 차단 28건 가운데 실제 critic 실행으로 이어진 것은 8건이고, 8건은 "위반 없음"이라는 말로 넘어갔다.
5. **"구현 먼저 금지" 룰은 한 번도 제대로 발동하지 않았다.** 같은 완료 어휘에 묶여 있었기 때문이다.

## 결정

1. **제외 조건은 매칭된 문장에만 적용한다.** 결합 트리거처럼 길이 0으로 매칭되는 경우는 문장을 특정할 수 없으므로 종전처럼 메시지 전체로 판단한다.
2. **룰마다 그 룰이 지키려는 행동의 주장에만 반응한다.** 분류기의 `chooseStopTrigger`가 정책 문장을 보고 아래 종류 중 하나를 고른다.

   | 종류 | 반응하는 주장 |
   |---|---|
   | mock | 같은 문장 안에서 "mock·stub으로 검증·통과했다"고 말할 때. 해소·라이브·금지·룰을 언급하는 문장은 제외 |
   | critic | 커밋 증거(해시·커밋·PR)가 있는 완료 선언, 커밋·머지·배포 동사, 리뷰를 생략하고 넘어갈 때 |
   | 주제 | 정책에 번호(①…)로 나열한 기능 이름과 빼기 제안이 같은 문장에 나올 때 |
   | 격리 | 실 데이터·프로덕션·live에 대고 "돌렸다·적용했다"고 말할 때 |
   | 구현 먼저 | "바로·먼저·일단 구현했다"고 말하면서 결정 문서나 합의를 언급하지 않을 때 |
   | 언어 | 한국어로 답하라는 룰. 40자 이상의 모든 답변을 한글 비율로 기계 판정 |
   | 그 외 | 완료 선언(기존 어휘에 "끝냈·마쳤·마무리했"을 추가) |

3. **critic 룰은 실행 증거로 판정한다.** 판정 방식은 `tool_evidence`이고, 최근 도구 호출 60개 안에 Agent·Task·Workflow·invoke-agent가 있으면 통과한다. 이를 위해 도구 기록 창을 20개에서 60개로 넓혔다. critic을 돌린 뒤 수정을 수십 번 하고 커밋해도 기록이 밀려나지 않게 하려는 것이다.
4. **적용 경로를 정한다.** 룰 설정은 룰 파일에 구워져 있어서, 업그레이드만으로는 새 발동 조건이 반영되지 않는다.
   - `forgen rule classify --stop-only [--apply]`는 Stop 설정만 다시 굽는다. 프로젝트 룰 파일이 같은 룰을 덮어쓰고 있으면 그 파일도 함께 고치므로 커밋해야 한다.
   - postinstall은 사용자 룰에 한해 이 작업을 한 번 자동으로 실행한다. 마커 파일은 `state/stop-retune-v2.done`이다.

## 결과 — 같은 2,671턴 리플레이

critic 룰의 판정에는 각 턴 직전의 실제 도구 호출 기록을 복원해 넣었다.

| 룰 | 이전 | 이후 | 비고 |
|---|---|---|---|
| 주제(농구 기능 빼기) | 45 | 4 | 남은 4건 중 2건은 실제로 "v1에서 빼자"는 안을 낸 정탐 |
| mock 검증 | 26 | 3 | 이전 26건은 단어 언급 위주 |
| 격리 검증 | 45 | 5 | 실 프로덕션 버킷에 돌린 실제 위반 1건 포함 |
| 구현 먼저 | 45 | 1 | "바로 구현했어" 1건 |
| critic | 34 | 72 | 이전에는 자기 신고로 대부분 통과했다. 이후 72건은 커밋이 있는 완료인데 최근 60회 안에 critic 실행이 없던 턴 |
| 하나 이상 차단된 턴 | 71 | 85 | |

차단 총량은 비슷하다. 다만 이전에는 같은 완료 어휘에 여러 룰이 함께 걸렸고, 이후에는 각 룰이 자기 위반에만 걸린다.

## 한계

- **룰에 프로젝트 범위 필드가 없다.** 그래서 농구 룰을 그 프로젝트로 한정하지는 못했다. 대신 발동 조건이 그 프로젝트의 기능 이름을 요구하므로, 사실상 그 프로젝트에서만 걸린다.
- **critic 룰은 최근 60회 안에 critic이 실행됐는지만 본다.** 그 critic이 이번 청크를 검토했는지는 확인하지 않는다. 도구 이름을 기록하지 않는 호스트에서는 항상 차단 쪽으로 판정된다.
- **정규식 판정이다.** 한국어 활용형을 모두 덮지는 못한다. 리플레이 표본은 이 머신 한 대의 30일 기록이다.
- **mock 룰은 마크다운 표 행을 판정하지 않는다(0.6.8).** 표 칸에 룰 이름을 적기만 해도 걸리던 오탐을 없앤 대가로, 표 칸 안에 쓴 실제 "mock 으로 검증 완료" 주장도 걸리지 않는다. 의도적으로 감수한 미탐이다.
